对齐原理与计算口径

地址顺序。 L 是物理层槽，B 是池内 block ID，N 是本卡页内 token，H 是存储的 KV head，C 是打包后的通道。Main 区同一层槽内的 block 连续，offset(L,B) = L × 池总 block 数 × 主 MLA 页字节 + B × 主 MLA 页字节。这里展示的是当前请求占用的 ID。分配器用整个池的 block 数计算 L 轴步长。

页与 ID。 KDA 沿用 MLA 页的步长。三组 KDA 各自有 block table，使用互斥的池 ID，同一组的 23 层使用相同的一串 ID。Indexer 和 draft 有独立的物理区域及页宽，也按池 ID 寻址。

先选 token 块，再算物理页。 当前四个传入值都满足这套配置的 kernel 和 checkpoint 粒度。固定版 vLLM 按每 token 576 B 把 MLA 块向上取整到能容纳一份 KDA 状态，再由 Ascend 按每 token 656 B 计算打包后的 MLA 页宽和 KDA padding。DCP 逻辑覆盖等于生效 block size × DCP。KDA 的 96 个头按 TP8 切成每卡 12 个。

模型按独享请求、无前缀复用计算。投机预留用于计算页数。max-model-len 是输入与生成预算之和，1M 档使用 (1M−1k)+1k。全池 null ID、模型权重、图内存和按引擎槽数分配的 RecoverSSM records 独立于该请求的 block 计费。

历史 DCP8 部署传入 768，启动后生效为 1536。本站默认直接传入 1536。其他页几何及无 DCP 场景按源码推算。实际 DCP8 启动还需校验 cp_kv_cache_interleave_size。两份基础状态页采用容量规划上界。
