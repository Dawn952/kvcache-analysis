对齐原理与计算口径

地址顺序。 L 是物理层槽，B 是池内 block ID，N 是本卡页内 token，H 是存储的 KV head，C 是打包后的通道。Main 区同一层槽内的 block 连续，offset(L,B) = L × 池总 block 数 × 主 MLA 页字节 + B × 主 MLA 页字节。这里展示的是当前请求占用的 ID。分配器用整个池的 block 数计算 L 轴步长。

页与 ID。 KDA 沿用 MLA 页的步长。三组 KDA 各自有 block table，使用互斥的池 ID，同一组的 23 层使用相同的一串 ID。Indexer 和 draft 有独立的物理区域及页宽，也按池 ID 寻址。

本地页与逻辑覆盖。 历史部署 CLI block size 为 768，有效本地 block size 为 1536。DCP8 下一个 MLA 历史 ID 覆盖 12288 个全局 token。KDA 的 96 个头按 TP8 切成每卡 12 个，状态数组沿用各自的形状。

模型按独享请求、无前缀复用计算。投机预留用于计算页数。max_model_len 列仍是输入与可生成预算之和。全池 null ID、模型权重、图内存和按引擎槽数分配的 RecoverSSM records 独立于该请求的 block 计费。

本页固定采用 A5 Atlas 的 1536-token 页几何。改变开关时重算页数、状态及池分项。实际启动时如发生重新定页，应当用对应部署的 cache spec 校准。两份基础状态页采用容量规划上界。
