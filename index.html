对齐原理与计算口径

地址顺序。 L → B → N → H → C 分别对应存储行（物理层槽）、池内 block ID、本卡页内 token、存储的 KV head 和打包后的通道。Main 区同一存储行的 block 连续，offset(L,B) = L × 池总 block 数 × 主 MLA 页字节 + B × 主 MLA 页字节。图中只展示当前请求占用的块。分配器用整个池的 block 数计算相邻存储行的间距。

页与 ID。 KDA 沿用 MLA 页的步长。三组 KDA 各自有 block table，使用互斥的池 ID，同一组的 23 层使用相同的一串 ID。Indexer 和 draft 有独立的物理区域及页宽，也按池 ID 寻址。

先选 token 块，再算物理页。 量化 MLA 按 576 B/token 选块，按 656 B/token 打包。BF16 MLA 的两个步骤都按 1152 B/token 计算。Indexer 的 INT8、FP8、BF16 分别用 130、132、256 B/token。DCP 逻辑覆盖等于生效 block size × DCP。KDA 的 96 个头按 TP 切分，TP8 每卡 12 个，TP16 每卡 6 个。

spec_num 对应 vLLM 的 num_speculative_tokens。Draft BF16 使用 1152 B/token。Draft C8 是按 576 B/token 的容量估算，静态 scale 另计，算子可用性和部署未验证。A5 Atlas 的 DSpark C8 容量口径

按独享请求、无前缀复用计算。每档以输入与生成预算之和设置 max-model-len，1M 档使用 (1M−1k)+1k。allocate_slots 先将主模型 token 和 lookahead 的和截断到模型上限，再由 Full Attention manager 按 DCP 逻辑块取整。因此用满本档预算时，lookahead 不会跨过模型上限占用新块。

MambaManager 在 align 模式按主模型进度管理 KDA 状态。单请求的稳态 Decode 每组保留 1 个运行状态块，RecoverSSM 关闭时再加投机状态块。跨块切换时旧块暂留，后续由 remove_skipped_blocks 释放。跨块重叠、额外 Prefill checkpoint、历史驻留、全池 null ID、权重、图内存和 RecoverSSM records 另计。
