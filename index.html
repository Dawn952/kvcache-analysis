对齐原理与计算口径

地址顺序。 L 是物理层槽，B 是池内 block ID，N 是本卡页内 token，H 是存储的 KV head，C 是打包后的通道。Main 区同一层槽内的 block 连续，offset(L,B) = L × 池总 block 数 × 主 MLA 页字节 + B × 主 MLA 页字节。这里展示的是当前请求占用的 ID。分配器用整个池的 block 数计算 L 轴步长。

页与 ID。 KDA 沿用 MLA 页的步长。三组 KDA 各自有 block table，使用互斥的池 ID，同一组的 23 层使用相同的一串 ID。Indexer 和 draft 有独立的物理区域及页宽，也按池 ID 寻址。

先选 token 块，再算物理页。 固定版 vLLM 按每 token 576 B 把 MLA 块向上取整到能容纳一份 KDA 状态，再由 Ascend 按每 token 656 B 计算打包后的 MLA 页宽和 KDA padding。DCP 逻辑覆盖等于生效 block size × DCP。KDA 的 96 个头按 TP 切分，TP8 每卡 12 个，TP16 每卡 6 个。

按独享请求、无前缀复用计算。每档以输入与生成预算之和设置 max-model-len，1M 档使用 (1M−1k)+1k。allocate_slots 先将主模型 token 和 lookahead 的和截断到模型上限，再由 Full Attention manager 按 DCP 逻辑块取整。因此用满本档预算时，lookahead 不会跨过模型上限占用新块。

MambaManager 在 align 模式只按主模型进度管理状态，不把 lookahead 当成 KDA token。表里的两个基础块和投机状态副本用于规划。实际驻留会随状态复用和 checkpoint 变化。额外 Prefill checkpoint、历史驻留、全池 null ID、权重、图内存和 RecoverSSM records 另计。
